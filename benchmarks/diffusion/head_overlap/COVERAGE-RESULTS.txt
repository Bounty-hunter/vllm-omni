Interpretation and limits
The two-group pipeline leaves the first forward exchange and final reverse exchange exposed. Total peer bytes are unchanged.
For first-head fraction x, a simple hideable-time estimate is min(A0,(1-x)*F)+min(A1,x*R).
F is the whole input exchange and R the whole output exchange. Fixed fence/copy costs and interference are omitted from that estimate.
A smaller first group can cover a larger remaining input exchange if A0 is sufficiently long. QKV input and output traffic are asymmetric.
Attention splitting also changes kernel tiling, scheduling waves and possibly SplitKV. Even widths are useful candidates, not a universal rule.
Communication grows linearly with tokens while attention grows roughly quadratically. Larger is not monotonically better in percentage E2E gain.
Small shapes retain the original whole settings. The A/A timing differences measure noise and must not be called optimization gains.
All eight small/mid-size A/A paired bootstrap intervals span zero; their median-ratio differences range from -0.19% to +0.54%.
This report freezes explicit cases; it does not implement or qualify a general production shape selector.
Quantization affects DiT linear weights; attention and direct CE buffers remain BF16 in these experiments.
The request budget excludes other communication such as encoder TP and VAE parallel exchanges.

Small-shape precision limit
The initial SP4/1024 split screen failed exact RGB. Whole-owned/borrowed agree; pure packed FA3 split arithmetic differs under auto SplitKV at1056. Fixed num_splits1 restores pure-attention equality. No backend default changed; small H3 selected stays whole.
The failed H3-small run is preserved with exit1 and clean restoration; it is excluded from accepted performance rows.
The diagnostic's exit0 means successful diagnosis, not that every compared output was equal.
No RGB tolerance was relaxed and no failed sample was removed from a performance average.
The fixed num_splits experiment was only a pure-attention diagnostic; a full-model fixed1 repair is not claimed.
The initial full-model diagnostic driver failed because its main guard was missing; the corrected r2 run completed.
Diagnostic scripts, logs, hashes and numerical outputs are in coverage-diagnostics.tar.gz and coverage-diagnostics.json.
