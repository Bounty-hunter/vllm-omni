Learning, execution counts and limitations
Each actual eager attention call executes one complete candidate core; output feeds the model. No extra forward/dummy kernel/probe graph is added.
Generic first-request Python body count5 =4 executed eager passes +1 capture recording; each component also executes its original denoising replays.
Qwen native calls300=60layers*5; FLUX125=25layers*5; Wan400=40layers*5*2experts.
H3 native150=50layers*(2 executed eager passes +1 capture recording); original validation replay1 and denoising replay6 remain.
These counts match baseline on every rank at every first shape. Hits have0 core/body Python calls and do not recapture.
First sampling has0 per-core host sync and0 captured learning timers. Header and finish are at most2 CPU-group gathers per learner, not per layer.
Steady learning timer records,event queries,exploration all_gather_object and sampling_host_syncs are0 on all ranks.
H3 original pipeline still calls101 all_reduce,61 Tensor.item and variable non-learning event APIs per request, equal in scope to baseline.
Existing GPU peer fences/dependency events execute during replay; zero learning APIs does not mean the graph contains no events or communication.
Preallocated events are recorded twice to realize handles and twice for each real sample; slow candidates and resource preparation have real once-per-shape costs.
Candidate native plans/buffers remain in the existing bounded plan/slot caches until graph-owner clear; they increase memory residency even after freezing.
Reported peak MB is the pipeline-provided metric, not a new allocator/residency measurement. In-process arm peaks share allocator history.
prepare_ms includes waiting behind existing GPU work and collective/resource preparation; it is not pure incremental CPU work.
Candidate proxy uses query tiles*heads/SMs plus estimated communication coverage; odd widths allowed, at most2 splits. No online global coefficient fit.
The proxy predicts candidates, not actual FA launch grids. Exact complete-core observations and conservative noise margins decide the frozen policy.
Only complete candidate cycles fully queued on every rank qualify. The start.query() readiness test is nonblocking; elapsed times are read at an existing sync.
Insufficient samples or gains retain whole. Qwen512/1K currently have no fully queued cycles and miss the previously verified Qwen1K fixed-split opportunity.
Wan17f also has no qualified complete cycles in the final matrix and retains whole despite a previously validated fixed4+6 benefit.
Wan33f final eight-pair blocks have opposite E2E signs and hundred-ms request jitter despite consistent2+8 choices and lower observed core times.
Their pooled median is not accepted as a stable benefit. Longer confirmation is reported separately; no outliers are removed.
The separate30-pair Wan33f confirmation reports+2.97%, 30/30wins; it does not erase the earlier noisy blocks.
Shape selection is graph-owned and reused on graph hits; no cross-process persistence or sharing between separate Wan expert graph owners.
A changed shape in this harness invalidates graphs and relearns. Metadata/strides/backend/SP are in the execution signature.
Unsupported mask/opaque metadata and small packed varlen remain whole; unexpected post-discovery signatures fail closed.
Only naturally existing pre-capture eager calls are usable. Whole-DiT graph replay cannot perform Python exploration inside its already captured layers.
Same borrowed output ownership is used for whole and adaptive. Removing a clone is not counted as overlap benefit.

Communication and split-cost interpretation
Request peer share is reused from independent coverage controls: (F+R)*calls/E2E, an ESTIMATE, not newly profiled request communication.
These controls include required peer fences and exclude encoder/VAE/other communication. Core peer share is C/(Awhole+C).
Control splitting tax applies only to its recorded partition; it cannot be assigned to a different newly learned5+9/3+11 partition.
Peer bytes do not decrease. Two groups hide part of traffic behind attention; first input exchange and final return remain exposed.
For small-first fraction x, ideal hidden time is min(A0,(1-x)*F)+min(A1,x*R). Net benefit also pays split-kernel/fence costs and any interference.
CE copies can still share DRAM/cache resources and require fences. This experiment does not establish a hardware cause for request jitter.
Large attention can cover more traffic, but growing quadratic attention lowers the communication fraction; percentage E2E gains need not rise monotonically.
Small-shape fallback eliminates split work at steady state; these A/A runs do not prove first-request nonregression.
Small uniform-split safety is not claimed. The prior H3 packed auto-SplitKV precision failure remains documented in COVERAGE-RESULTS.txt.
No HTTP/concurrency/torch.compile/hybrid-parallel qualification or production-default selector is claimed.
