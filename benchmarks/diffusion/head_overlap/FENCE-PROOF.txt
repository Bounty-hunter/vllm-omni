Final experimental schedule: fence and lifetime argument

Unequal head groups
For world size W and positive per-rank group widths h_g, define
o_g = W * sum(h_i for i < g). Rank r computes the global head interval
[o_g + r*h_g, o_g + (r+1)*h_g) for group g. The W rank intervals partition
[o_g, o_g + W*h_g), and adjacent groups have adjacent endpoints. Requiring
W * sum(h_g) == total_heads therefore covers every head exactly once.
Forward source offsets and reverse destination offsets use this same mapping.
Joint Q/K/V use the rank's interval; joint outputs are replicated as before.

Group widths and offsets are resolved before capture, and actual widths are
part of the resident plan key. Each forward buffer uses its group's width.
Changing the ratio never rebinds the geometry retained by another graph.
For the same number of groups, unequal sizes change neither the number of
memcpy submissions nor peer fences. Summed transferred head widths, hence
total bytes, are unchanged. These are scheduling changes, not byte reduction.
All reuse arguments below depend on disjoint buffers and happens-before
edges, not equal group widths; every incoming-ready and output-ready fence
is retained. Group ratios must match across ranks, just as chunk counts do.

partition_probe.py checks dense and front-joint inputs against a global
reference while 16 graphs remain resident, with delayed consumers at SP2/4.
The model partition experiments additionally compare seeds 42/43/44 bitwise.
Exact source identities and tested ratios are in PARTITION-RESULTS.txt.

Assumptions
- All ranks call the same head-group schedule on one owning compute stream.
- Each head group owns a distinct forward buffer. Output assembly uses a
  separate symmetric buffer; it never aliases any forward buffer.
- The public native wrapper returns an independent clone on compute.
- Every reverse source stays alive until compute's final wait is enqueued.
- Shape changes synchronize before releasing the previous fixed plan.

Input-buffer reuse
1. A call's final peer fence follows every reverse transfer.
2. Each reverse transfer waits for the corresponding attention-produced event.
3. Hence completion of the final peer fence implies that all ranks finished
   every attention read from the current call's private input buffers.
4. Compute waits for that final fence before returning. The following call's
   local prefill and producer event follow this wait on the same compute stream.
5. New local or peer writes to input buffers therefore cannot overwrite a
   previous attention consumer, even when the host queues calls ahead.

Output-buffer reuse
1. After the final wait, the native wrapper clones the assembled output on
   compute. This clone is the only post-return reader of the private output pool.
2. The next call's local input prefill follows that clone on compute.
3. The peer communication stream waits for completion of this local prefill
   before sending F0 and entering F0's incoming-data-ready peer fence.
4. Completion of F0's fence therefore also acknowledges completion of every
   rank's previous output clone.
5. All new attention groups depend on F0-ready, directly or through the owning
   compute stream. Every new reverse transfer depends on its attention output.
6. No new reverse write can overwrite another rank's previous output clone.

The preceding final fence protects old input readers; the next F0-ready fence
protects old output copy-outs. An additional entry peer barrier is redundant.
For two groups this leaves two forward-ready fences and one final output fence.
No incoming-data-ready or final-output-ready fence is removed.

Independent output ownership
The public wrapper's clone preserves outputs held across later calls. Later
projection kernels read this independent tensor, not the transport output pool.
The lower-level profiling plan explicitly returns pooled storage. Its caller
must consume/copy it on the owning compute stream before the next invocation.

CUDA allocator lifetime
Raw CE reads are not visible to PyTorch's allocator. The Python source list
retains each attention output through insertion of compute's final wait. Storage
freed afterward can only be reused after this wait on the same compute stream,
which also orders all reverse reads. No per-layer record_stream retention is
needed; this avoids keeping temporary storage alive across many DiT layers.

Adversarial validation
stress_fences.py alternates two immutable input sets, deliberately delays both
CPU and GPU output consumers on different ranks, queues 16 calls without an
inter-iteration host barrier, then compares every saved output bitwise to a
fully synchronized reference. This targets the output-copy-out race directly.
The independent global-reference suite also covers layout changes, 2/4 groups,
GQA/mask/rear-joint fallbacks and the single-compute-stream guard.
Consult the final run log for actual validation results.

Staged local prefill
schedule_probe.py also tests placing only F0's local copies before enter, then
issuing the remaining local copies on compute while F0 runs on communication.
The previous final fence still protects every old forward-buffer reader.
Distinct forward buffers make F1-local and F0-peer destinations disjoint; QKV
sources were produced before enter. Every local prefill finishes on compute
before its attention consumer. enter still follows the previous copy-out, so
the F0-ready acknowledgement and all three peer fences remain unchanged.

Explicit static-graph output slots
native_prefilled.output_slot(key) opts a fixed graph/layer into a private
symmetric output slot. The caller warms the slot before capture, consumes it
on the owning compute stream, and does not expose it beyond its next replay.
The graph records reverse writes directly to this slot instead of cloning the
shared output pool. Ordinary, unscoped attention results still own their clone.

A following F0-ready fence acknowledges that every rank reached enter after
the preceding compute consumers. No reverse write, including a later reuse of
the same slot, can pass that acknowledgement. Incoming reverse writes still
finish at the slot's final output-ready peer fence before local consumption.
Unique layer keys additionally prevent different layers from sharing storage.
The ContextVar scope resets on exceptions; keys must identify a fixed layout.
Destroy captured graphs before clear() synchronizes and releases their slots.
The experiment caps residency at 128 slots and clears it on canvas changes.

Optional single-slot graph lifetime
A fixed-canvas graph may instead reuse one output key across layers when its
attention consumers finish on compute before the next attention's enter.
Those consumers precede enter on compute; F0-ready runs after that enter on
communication and acknowledges all ranks. Every following reverse write is
ordered after F0-ready. Thus no rank can overwrite a preceding layer's borrowed
output until all ranks have acknowledged its consumers, even with asymmetric
progress. The final output-ready fence still protects incoming current writes.
This argument depends on the consumer boundary, not on different layer keys.
It does not permit retaining borrowed attention outputs past the next reuse.
The graph's projected hidden result has separate storage and remains its output.
The model comparison and asymmetric delayed-consumer probe validate this
explicit one-slot scope; ordinary attention output ownership remains unchanged.

graph_slot_stress.py verifies both retained ordinary
